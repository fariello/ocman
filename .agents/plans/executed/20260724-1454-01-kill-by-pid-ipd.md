# IPD: `ocman kill` accepts a PID and shows the same enriched preview before killing

- Date: 2026-07-24
- Concern: UI/UX + capability (CLI). `ocman kill` today targets by the current directory or a
  case-insensitive PATTERN (cwd/project/session). It cannot target a specific PID, and a numeric
  arg is NOT matched against pid (it falls through to substring matching over session ids, which is
  misleading). The maintainer wants `ocman kill <PID>` to work and to show the SAME enriched
  preview added by 20260724-1057-01 (PID / Kind / Uptime / Project / Session + provenance, and
  Listener/Auth when a listener exists) before killing.
- Scope: `ocman/cli.py` (`cli_kill` arg handling + a new PID-target resolver; the `kill` subparser
  help text only if needed), `tests/test_ocman.py`. No DB change, no dependency, no signal-handling
  change. Builds on the just-executed `.agents/plans/executed/20260724-1057-01-kill-preview-detail-ipd.md`.
- Status: EXECUTED (2026-07-24; maintainer approved; 528 passed / 2 skipped)
- Target version: rides the in-flight 1.3.0 line (final promotion still paused).
- Approval: awaiting plan-review + maintainer approval

## Evidence
- Arg surface: the `kill` subparser has one positional `pattern` (nargs="?", default None) plus
  `--dry-run`, `-9/--force`, `-y/--yes` (cli.py:6456-6464). Dispatch at cli.py:6943 (`group == "kill"`).
- `_kill_targets(cwd, pattern)` (cli.py:12372): `pattern is None` -> `_reconnect_candidates(cwd)`
  (current-dir); else `detect_running_instances()` filtered by `_instance_matches_pattern`.
- `_instance_matches_pattern` (cli.py:12354-12369) matches over cwd/project/session id/ids/title/
  directory/project_id, NOT pid. So a numeric arg does not target a PID today (it can only
  coincidentally substring-match a session id) - this is the gap.
- Preview + choose rendering already enriched (cli.py ~12430 block, ~12405 choose list) and reuse
  `_sess_str` (module scope). A PID target that carries the same dict fields renders for free.
- Validation primitives ALREADY EXIST: `_pid_looks_like_opencode(pid)` (cli.py:12104, reads
  /proc/<pid>/cmdline), own-user check via `os.stat("/proc/<pid>").st_uid == os.getuid()`
  (pattern used at cli.py:12155 and 12386), `_reuse_guard_ok` (cli.py:12140, re-validated before
  each signal), `_pid_is_gone` (cli.py:12114). `detect_running_instances()` returns the enriched
  dicts we prefer when the PID is among them.

## Design decisions (RESOLVED with maintainer 2026-07-24)
- PID surface: RESOLVED = BARE NUMERIC POSITIONAL. An all-digits positional arg is treated as a
  PID; any non-all-digits arg remains a PATTERN. Trade-off ACCEPTED: a purely-numeric string can no
  longer be used as a substring PATTERN filter (documented in help text; note that this is a rare
  filter and cwd/project/session ids are not all-digits).
- PID present but NOT in the enriched detected set: RESOLVED = KILL WITH A PARTIAL PREVIEW + CAVEAT.
  Show PID + cmdline + uptime read from /proc, label the fields we cannot derive (Project/Session)
  as "unknown (pid not in detected instance set)", proceed after confirm. The reuse guard still
  protects at signal time.
- PID that is NOT an own-user opencode process: RESOLVED = REJECT BEFORE PREVIEW, loud. Validate
  own-user AND looks-like-opencode before showing any preview; `die(...)` otherwise. Matches the
  existing own-user-only + opencode-only posture.

## Non-goals
- No `--pid` flag (bare positional was chosen); can be added later if the numeric-pattern trade-off
  bites. No multi-PID list in one invocation (single PID; the existing multi-instance PATTERN path
  already covers "several at once"). No change to `reconnect`. No cross-user killing. No Windows/mac
  support (kill stays Linux-only via the existing detection guards).
